## 0. 正确功能验证（real path）——判「过」的唯一口径

「通过」只能由真实链路产出。凡是用注入/模拟把界面点亮、再拿一行日志判过的，都算
**旁路（bypass）**，一律不算通过。每项的真依赖 / 可观测判据 / 不算数的旁路：

| 段 | 真依赖 | 可观测判据 | 不算数的旁路 |
|---|---|---|---|
| `env` | 真路由器 | `wapi connect` 后真的拿到 `192.168.x.x` | 看到 `connect` 字样就过 |
| `states` | 无（纯本地） | 6 个表情上屏、切页面编号不变 | 只读日志不隔帧比 |
| `standby` | 无 | 暗色时钟真的上屏 | — |
| `wake` | 无 | 首按只唤醒、无业务动作 | — |
| `keys` | 网络 + 一次真 `ask` + bridge 模型表 | 气泡真的滚动、`Model -> <新模型>`、`New session requested.` | **只判 `[key] … -> hit`**（按了没反应也算过）← 10-30 踩过 |
| `remote` | 网络 + broker + bridge + agent | `State≠Offline` + `Backend=up` → 一轮到底 | 只看 `Prompt sent` |
| `approval` | **`remote` 已在跑** + coding agent 真发工具调用 | 真 agent 发起工具调用 → 审批页 → 板键通过/拒绝 → 回合继续/终止 | **`rpending` 假审批**；只看 `Approved (debug).` |
| `notify` | 网络 + Gerrit/Jira MCP + **屏醒着** | 真事件 → 通知页 → 5s 自退 / 按键退出 | **`notify_inject` 注入**（只证明页面画得出来） |
| `ask` | 网络 + LLM key | 真 LLM 回复落到气泡 | 关键词快路径冒充「文字走通」 |
| `ptt` | 网络 + 豆包 key + 麦克风 | 真说话 → ASR 出字 → 回复 → 喇叭出声 | 文件式/回灌音频 |

**结论**：`keys / approval / notify / ask / ptt / remote` 的正确路径全部经过 Wi-Fi。
Wi-Fi 不通时，这些项只能是**阻塞（BLOCKED）**，不得被弱判据判成通过。
`func-test.sh` 会用 `rstat` 读板子自报的远控状态做依赖闸门，不满足就记 ⛔。

## 1. 先记住三条固定规则

- **页面只有 5 个**：宠物主页 / 聊天屏 / 审批页 / 通知页 / 待机时钟。粒子流页已删。
- **一只宠物贯穿全部页面**：形象 4 种（白猫 / 青蛙 / 棕狗 / 粉猪，黑色已删）。
  每次烧录后首次启动随机定一只并存下来，运行中不换；不同页面、不同状态只是
  同一只宠物的不同表情。
- **通知有独立页面**：不再是屏顶小 toast（小屏显示不全），改为独立整页，
  停 5 秒自己退，任意键可提前退；这一按键被通知页吃掉，不会顺带翻页或答审批。

三种覆盖关系（已实现，2026-11-02 按新需求改）：

| 场景 | 结果 |
|---|---|
| 通知页 vs 审批页 | 审批优先。审批在屏上时来的通知先排队，只留最新一条，等审批收起再上屏 |
| 通知页 vs 通知页 | 后到覆盖：换成新那条，5 秒窗口重新计时 |
| 通知/审批 vs 待机时钟 | **来了就唤醒锁屏界面**（不再丢弃）。通知：上屏后约 5s 自动关闭、然后**回到锁屏**；审批：**长亮不自动退**（停在审批页直到板键通过/拒绝） |

## 2. 需要人工按键的项：会话终端 check → 你确认 → 立刻执行

凡是必须**在真机上按一次键**才能判定的项（通知页按键退出、审批 S2 通过 / S3 拒绝、
keys 各项、ptt 的 S1），一律按这个流程走，**不要要求人盯着真机屏幕等**：

1. **先在会话终端给 check**：写清楚要按哪个键、按下去之后屏幕该出现什么、判据是什么
   （例：`看到通知页 → 按 S2 → 期望 [key] notice: … dismissed + hidden (dismissed by key)`）。
2. **等你在 PC 上的会话里确认**（口头「好」/「按」即可）。确认前我不发起那一轮。
3. **你确认后我立刻下发「执行按键操作」的那段**，中间不插别的动作、不先做别的检查——
   通知页只挂 5 秒，拖久了窗口就过了。
4. **你确认后很久没按，就不要再等了** —— 直接停下来排查，不要开长窗口空耗。
   「很久没按」= 你在 UI 上没看到该变化，不是按键坏了。按这个顺序查：
   - 事件到底有没有来：`[notify] gerrit poll: N new` / `[Notify]: Gerrit #…`；
     MCP 是否 `Total remote tools: 0`（掉了就 `mcp_discover` 重连）
   - 页面有没有被丢掉：`deferred (approval page up)` = 被审批页顶掉（排队中，属正常）；
     通知不再因待机被 `dropped`——待机时钟会被通知**唤醒**（先 `standby clock hidden` 再 `show`）
   - 事件来了、也没被丢，但屏上什么都没有（`[lvgl_notice] show:` 有、人没看到）
     → 这是**渲染侧的问题**，要单独查，不要再用「再等一条事件」来掩盖
   - 控制台是不是已经不可用：心跳（`[lvgl_ui] hb …` / `[lv_nuttx_lcd] rate:`）还在滚，
     但 `help` / `notify_status` 这类本地命令 20 秒内没有任何回包 → CLI 线程没了，
     整机复位，别继续在这一炉上验
   排查结论要贴到会话终端，再决定下一轮；不要「再等一次试试」式地重复。

反过来，**能由串口日志自己判的不要叫人**：`[lvgl_notice] show: Gerrit|Jira`、
`[lvgl_notice] hidden (auto-dismiss)`、`[notify] gerrit poll: N new`、TLS/MCP 是否通、
`[key] … -> hit` 这类，我自己盯串口判完把结果贴到终端。

## 顺序（10 项，按依赖排）

1. `env` — 板子停在 `vela>`、时钟已对齐、网络确实通
2. `states` — 6 种状态逐个点亮（同一只宠物的 6 个表情）+ 宠物/聊天两页可切；
   期间读一次形象编号，来回切页后再读，**编号不变**才算过
3. `standby` — 空闲 60 秒自动淡入暗色时钟
4. `wake` — 待机时第一下只唤醒，不顺手答掉审批/翻页
5. `keys` — 无审批时：上滚 / 下滚 / 换模型 / 新会话 / 组合取消
   （真判据是效果：气泡真的动、`Model -> <新模型>`、`New session requested.`；
   只看到 `[key] … -> hit` 不算过——那是按键被收下了，不是功能生效）
6. `remote` — 看链路与后端 → 发目标 → 等 coding agent 真的动代码
7. `approval` — 审批页出现 → 能被时钟盖住 → 唤醒后原样保留 → 通过、拒绝各落地一次
   （审批的「因」是第 6 步 agent 要改文件/执行命令；`rpending` 是假审批，只在 `ALLOW_BYPASS=1` 下可跑）
8. `notify` — 真事件上屏：等 Gerrit/Jira 的一条真事件 → 通知页 → 停 5 秒自己退；
   再等一条真事件，在 5 秒窗口内按键提前退。
   （注入版 `notify_inject` 只在 `ALLOW_BYPASS=1` 下可跑，结果标「旁路」，不算过）
9. `ask` — 文字一轮：用户气泡 → 助手回复 → 8 秒让位回宠物；关键词快路径不经 LLM 也能走完
10. `ptt` — 按住 S1 说一句 → 识别成气泡 → agent 回复并出声

### 为什么 `remote` 必须排在 `approval` 前

审批唯一的真来源就是 PC 侧 coding agent 要改代码/执行命令——没有第 6 步的 agent，
板上就只能用 `rpending` 造假审批。所以 6 → 7 是硬依赖。

本轮（2026-10-30 定）这个「因」固定成两件事，已写进 `func-test.sh`：

- 改的文件：`~/project26/vela-miwear-bes-o62-25rc05-lc3/apps/examples/hello/hello_main.c`
  —— 就是 `vela/apps` 这个项目里的文件（该目录是独立 git 仓库，push 远端为
  `ssh://<用户名>@gerrit.pt.mioffice.cn:29418/vela/apps`）
- 改完要推到：`https://gerrit.pt.mioffice.cn/c/vela/apps/+/10334000`
  —— 给这个**已有 change 更新 patchset**，不新推 change

`func-test.sh` 的 `approval` 段现在会先 `rask` 让 agent 真去改这个文件（只改文件，
不 commit、不 push），审批页因此有真来源；拒绝分支也一样再发一条真 `rask`，不干等。
推送这一步不在 `approval` 的判据里：工作副本已存在，但 **10334000 的提交还没 fetch**
（`refs/changes/xx/10334000/*` 一条都没有），所以要推得先 fetch，否则就是没前置。

### 为什么 `notify` 不需要跟着往前挪

`notify` 的真依赖只有「网络 + MCP 已配 + 屏醒着」：`notify_service` 只是问 Gerrit
「`status:open` 里有没有比上次更新的 change」，谁提的 change 都算，不需要我们自己动代码
（2026-10-30 实测：一行没改也真收到 11009137/11009149/… 一串）。它排在 7 之后还更稳：
审批页在屏时通知会被顶成「排队」，等审批收起才上屏，两件事叠在一起容易判错。

> 注意：给已有 change **更新 patchset 不会**产生通知事件——去重按 change 号（`id > last_max`），
> 更新 patchset 不改 change 号。要拿「自己的改动」触发通知，得推一个**新 change**。

## 这两段现在怎么判（脚本里的判据）

`states`：

1. `set_pet 0…5` 各一次 → 屏上依次换 6 个表情
2. `set_ptype`（不带参数）→ 回一行「当前固定形象编号」，记下来
3. `set_page 0` → `show_chat` → `set_page 0`（宠物页 ↔ 聊天屏来回）
4. 再 `set_ptype` → 编号与第 2 步相同 → 页面上打出「形象没随页面变」

`notify`（真事件版）：

1. 待机与否都可以等事件——**通知会唤醒锁屏界面**（不再需要先 `set_page 0` 保活）
2. 等 Gerrit/Jira 的一条真事件 → 通知页弹出（若在待机，先 `standby clock hidden` 再 `show`）→ 约 5 秒后自动关闭、回到锁屏（`standby clock shown` + `hidden (auto-dismiss)`）
3. 再等一条真事件 → 在 5 秒窗口内按 S2；页面立刻关掉（`dismissed (swallowed)` + `hidden (dismissed by key)`），并且**没有**发生滚动或审批动作
4. 窗口内没有真事件到 → 本项记「阻塞」，不用 `notify_inject` 顶替

`notify`（旁路版，`ALLOW_BYPASS=1`，只证明页面画得出来）：注入 Gerrit → 弹出 → 5s 自退；
注入 Jira 且每 3 秒补发 → 按键关掉。**结果标「旁路」，不算通过。**
4. 判据是「页进 → 页自己出」和「页进 → 按键出」，而不是以前的小 toast 出现/淡出

## ⚠️ 顺序不能乱

- `remote` 必须在 `approval` 之前：审批的「因」是 agent 要改代码，没有 remote 只能假审批
- `approval` 必须在 `keys` 之后：审批页在场时按键落在审批键表，不是滚动键表
- `wake` 必须紧跟 `standby`：待机首按被吞，只有这时机验得到
- `notify` 排在 `approval` 之后：审批页会把通知顶成「排队」，叠在一起容易判错；
  而且 `notify` 的依赖（网络 + MCP + 屏醒着）跟前六项毫无关系，放最后不影响任何东西
- `notify` 里按键退出的那一下，必须在通知页还在屏上时按（真事件版只有 5 秒窗口；
  旁路版靠脚本持续补发把页面挂住，但旁路不算过）
- 等真事件期间**不需要**保活：通知来了会唤醒待机时钟、上屏、约 5s 自动关、再回到锁屏
  （2026-11-02 实测；旧「待机丢弃」行为已删除）
